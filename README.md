# GitHub Search — поиск и скачивание проектов с GitHub

Два инструмента в одном репозитории:

| Часть | Где | Что это |
|---|---|---|
| **Веб-версия** | [`index.html`](index.html) | Одностраничный инструмент: ноль зависимостей, ноль сборки, работает прямо в браузере |
| **Android-приложение** | [`android-app/`](android-app/) | React Native + Expo: то же самое, но нативно, с избранным, кешем и входом в GitHub |

Живая версия сайта: **https://notkovvik.github.io/GitHub-Search/**

---

# Веб-версия

Одностраничный веб-инструмент для поиска и скачивания проектов с GitHub. Введите ник, ссылку на репозиторий или поисковый запрос — откроется страница с авторами и репозиториями, откуда в один клик можно скачать код или файлы релизов.

Никаких установок, регистраций и зависимостей: чистый HTML + CSS + JavaScript в одном файле.

## Что умеет

- **Три режима поиска в одной строке**
  - `torvalds` — открывает профиль пользователя
  - `https://github.com/torvalds/linux` — открывает владельца с фильтром по репозиторию
  - `linux kernel` — открывает страницу результатов с авторами и репозиториями
- **Страница результатов** — сверху авторы, снизу репозитории. Если авторов нет, секция не показывается.
- **Скачивание в один клик**
  - **Скачать код** — ZIP-архив ветки по умолчанию
  - **Файлы релизов** — ассеты последнего релиза с размерами
  - **Все релизы** — переход на страницу релизов репозитория
- **Профиль** — аватар, био, компания, локация, блог, подписчики; статистика (проектов, звёзд, языков); поиск по репозиториям и сортировка (обновление, дата, звёзды, алфавит); подсветка репозитория при переходе по `#user/repo`
- **Живые подсказки** при вводе — параллельно ищутся пользователи и репозитории
- **Локализация** — русский и английский, автоопределение по языку браузера (`ru`, `uk`, `be` → русский)
- **Тёмная и светлая темы** — по системным настройкам
- **Кеш API на 10 минут** — повторные заходы почти мгновенные
- **Персональный токен GitHub** (опционально) — лимит с 60 до 5000 запросов в час. Хранится только в браузере.

## Как пользоваться

1. Откройте страницу.
2. Введите ник (`torvalds`), ссылку (`https://github.com/torvalds/linux`) или запрос (`machine learning`).
3. Нажмите **Найти**.
4. На странице результатов: **Авторы** — карточки с кнопкой «Профиль»; **Репозитории** — карточки с кнопками **Открыть**, **Скачать код**, **Файлы релизов**.

## Размещение

**Локально:** скачайте `index.html` и откройте в браузере.

**GitHub Pages:** положите `index.html` в корень репозитория → Settings → Pages → Source: `Deploy from a branch` → `main` / `root`.

**Свой хостинг:** загрузите `index.html` в любую папку — Apache, Nginx, Netlify, Vercel, Cloudflare Pages.

## Технические детали

- Один HTML-файл, ноль зависимостей, ноль сборки.
- Роутинг на hash: `#login`, `#login/repo`, `#q=запрос`.
- Кеш API в `localStorage`, TTL 10 минут; язык интерфейса и токен — тоже там.
- Поддержка `prefers-color-scheme` и `prefers-reduced-motion`, адаптив до мобильных.

# Android-приложение

Нативное приложение на **React Native 0.74.5 / Expo SDK 51** (TypeScript). То же ядро, что у веб-версии, плюс офлайн-хранилище, избранное и вход в GitHub.

## Возможности

- **Поиск** — живой поиск авторов и репозиториев без нажатия Enter (ввод с задержкой 420 мс, минимум 2 символа), свайп между вкладками «Репозитории» и «Авторы», бесконечная прокрутка с пагинацией
- **Экран репозитория**
  - описание, даты создания и обновления, бейджи языка, звёзд, «архив», «форк»
  - статистика: звёзды, форки, issues
  - **Скачать код** — ZIP ветки по умолчанию
  - **Открыть сайт** — homepage или GitHub Pages
  - **Файлы релизов** — ленивая загрузка, список ассетов с размерами, «Все релизы»
  - темы, разбивка по языкам, лицензия, размер, наблюдатели, переход на профиль владельца
  - закладка в избранное
- **Профиль** — репозитории с фильтром по названию/языку/теме, сортировки, статистика, вкладка «О пользователе»
- **Избранное** — репозитории и авторы
- **Настройки** — состояние аккаунта, остаток лимита GitHub API с прогресс-баром, размер кеша и его очистка, очистка истории, переключатель ссылок GitHub
- **Вход в GitHub** — токен хранится в Android Keystore (`expo-secure-store`), лимит поднимается с 60 до 5000 запросов в час
- **Диплинки и App Links**
  - `https://github.com/owner/repo` (в том числе `…/issues`, `…/releases`) открываются прямо в приложении
  - `ghexplorer://settings`, `ghexplorer://favorites`, `ghexplorer://search?q=запрос`, `ghexplorer://owner/repo`, `ghexplorer://owner`
- **Оформление** — тёмная и светлая темы по системной, анимации появления вкладок и карточек, аккуратные safe-area отступы

## Установка APK

Готовые сборки — в разделе [Releases](../../releases):

| Файл | Для кого | Размер |
|---|---|---|
| `GitHub-Search-arm64-v8a.apk` | почти все современные телефоны (рекомендуется) | ~26 МБ |
| `GitHub-Search-armeabi-v7a.apk` | старые 32-битные устройства | ~21 МБ |
| `GitHub-Search-universal.apk` | если не знаете архитектуру — подойдёт любой | ~67 МБ |

Установка: скачайте APK на телефон, откройте, разрешите установку из неизвестных источников. Или через adb:

```bash
adb install -r GitHub-Search-arm64-v8a.apk
```

Не знаете свою архитектуру? Посмотрите в приложении «Настройки → О телефоне» или установите universal.

## Сборка из исходников

Нужны: Node.js 18/20, JDK 17, Android SDK (platform 34, build-tools 34, NDK 26.1.10909125).

```bash
cd android-app
npm install

# сборка + установка на подключённый телефон
npx expo run:android --variant release

# или только APK
cd android
./gradlew :app:assembleRelease            # универсальный
./gradlew :app:assembleRelease -PdshAbi=arm64-v8a      # только arm64
./gradlew :app:assembleRelease -PdshAbi=armeabi-v7a    # только armeabi-v7a
```

Готовый APK: `android/app/build/outputs/apk/release/app-release.apk`.

> Флаг `-PdshAbi` (добавлен в `android/app/build.gradle`) фильтрует упаковку по архитектурам. Стандартный `-PreactNativeArchitectures` ограничивает только компиляцию — в APK всё равно попадут все ABI из префаб-библиотек React Native.

## Вход в GitHub

**По умолчанию — Device Flow.** Нажимаете «Войти»: приложение запрашивает код, копирует его в буфер обмена и открывает страницу GitHub в браузере — остаётся вставить код и подтвердить. Токен сохраняется в защищённом хранилище Android.

**Опционально — вход в один тап (web-flow с PKCE).** Чтобы включить:

1. В настройках OAuth App на GitHub добавьте **Authorization callback URL**: `ghexplorer://auth`
2. Создайте в папке `android-app/` файл `.env`:
   ```
   EXPO_PUBLIC_GH_CLIENT_SECRET=ваш_client_secret
   ```
3. Пересоберите приложение — при входе сразу откроется страница авторизации GitHub, кода вводить не нужно.

`.env` уже в `.gitignore`. Учтите: секрет вшивается в бандл приложения, поэтому его не стоит публиковать в Google Play — для личной сборки это нормально.

## Ссылки github.com в приложении

Начиная с Android 12 система отдаёт web-ссылки браузеру, пока приложение не одобрено вручную (домен `github.com` нельзя верифицировать — нужен `assetlinks.json` на самом github.com). Один раз включите:

**Настройки → «ССЫЛКИ GITHUB» → «Открыть настройки ссылок» → включить `github.com`**

После этого ссылки вида `github.com/owner/repo` открываются в приложении, а служебные страницы (`/notifications`, `/login`, `/marketplace`) и профили (`github.com/username`) по-прежнему идут в браузер.

## Лимиты GitHub API

| Режим | Обычные запросы | Поиск |
|---|---|---|
| Без входа | 60 в час | 10 в минуту |
| С токеном | 5000 в час | 30 в минуту |

Кеш ответов — 10 минут. При исчерпании лимита приложение показывает кнопку входа прямо в экране ошибки.

## Известные ограничения

- **Скачивание идёт через браузер.** «Скачать код» и файлы релизов открываются в браузере, загрузку ведёт он же (файлы попадают в «Загрузки»). Встроенного менеджера загрузок пока нет.
- **Страница авторизации открывается в браузере, а не во встроенном окне.** Пока приложение является обработчиком `github.com`, системный Custom Tab для этого домена недоступен — система возвращает запрос в само приложение.
- **Ссылки на профили** (`github.com/username`) открываются в браузере: фильтр ссылок намеренно ограничен путями `owner/repo`, иначе приложение перехватывало бы и служебные страницы.
- **Релизные APK подписаны debug-ключом** из шаблона Expo — для локальной установки и тестов. Для Google Play нужен свой ключ.
- **`minSdkVersion: 33` в `app.json` не применяется** — этот параметр работает только через `expo-build-properties`, поэтому фактический `minSdk` равен 23, а `targetSdk`/`compileSdk` — 34.
- **Только Android** — проект собирался и тестировался на Android 16 (arm64).
